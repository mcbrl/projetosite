When we talk about API integration, we can mention a wide variety of technologies that do this. One of them is WSO2. Although this open-source tool has problems, such as a very steep learning curve, some companies like eBay, Cisco, HP, and others use WSO2 as a *middleware* tool . But what does all this have to do with **the Internet of Things**?

## **Check out WSO2 features: Integration and Orchestration with Internet of Things processes.**

The **Internet of Things** is driving new business models in a variety of markets. We see examples daily in transportation, healthcare, automotive, manufacturing, and others. However, the implementation of the Internet of Things depends on integrating information from devices with systems and the ability to manage this information. WSO2 has functionalities in its Integration Platform that improve service and process orchestration for IoT ( *Internet of Things* ) applications, and these are:

- **WSO2 Message Broker 3.0 and WSO2 Enterprise Bus (ESB WSO2) 4.9**The versions support *Message Queuing Telemetry Transport* (MQTT). This is a lightweight messaging protocol, widely adopted for connecting devices, sensors and *gateways*.
- **WSO2 Business Process Server (WSO2 BPS) 3.5**It has an engine. *Open Source Activities* for business process management (BPM). This makes use of *Business Process Modeling Notation (BPMN) 2.0*, which is recognized as one of the most comprehensive *software* for process modeling.
- **WSO2 Data Services Server** **(WSO2 DSS) 3.5**Adds support for the protocol. *Open Data* 4.0 (OData), thus providing the ability to query data from a variety of sources via standard, open RESTful APIs. These capabilities can work on both mobile devices and web systems, whether cloud-based or not.

## **Optimizing the new features**

To assist the WSO2 Message Broker, WSO2 ESB, and WSO2 BPS and the **WSO2 Application Server**The Integration Platform also includes the WSO2 API Manager. This allows for API management across connected devices and the messages being exchanged. With 2,2 trillion customer transactions per year on the platform, WSO2 offers the scalability and reliability to handle large volumes of IoT-focused interactions.
Furthermore, all products on the platform are fully enabled for use in *Cloud,* so that the same software can be deployed on servers within the company (*on-premises*), or in the cloud. This provides deployment flexibility that some companies require, as they prefer to have hybrid environments for their solutions.
"*Increasingly, we are seeing global corporate clients standardizing our **WSO2 Integration Platform**, for their Internet of Things implementations.* These range from car transportation, manufacturing, construction, healthcare, communications and smart cities,” said Edgar Silva, VP Latam WSO2.
"*With the addition of MQTT support for connecting to devices from **Internet of Things**With BPMN 2.0 for IoT-aware process modeling, and OData 4.0 for IoT data APIs, we are building on our commitment to delivering industry-standard technologies that address enterprise IoT solution demands.*"Edgar Silva emphasized."

## **WSO2 Message Broker 3.0**

O **WSO2 Message Broker** It is a server that supports high availability (HA). It also has the ability to scale to multiple servers within a cluster, and consequently, manage points of failure. It is also designed to handle persistent messages that are queued, subscribers, or even attacks.
In this version 3.0, the **Message Broker** It has new features and enhancements to offer companies a scalable architecture. This is intended to easily manage the high volume of messages and the demands of the designed solutions.

- O **MQTT protocol** It connects remote devices and sensors. In this way, machine-to-machine (M2M) communication can generate millions of simultaneous events per second.
- The new *plug-in* For relational databases, it allows developers to configure relational databases. This makes message storage easier.
- Scalability based on high availability (HA) features allows for easy scaling of the messaging system. This is based on message growth. This was first introduced in version \[version number missing from original text\]. **2.0 do *Message Broker***.
- New functionality for coordinating *cluster* server-side. It eliminates the need for third-party technologies, such as *ZooKeeper*which reduces the complexity and maintenance requirements of deployment.

## **WSO2 Enterprise Service Bus 4.9**

**WSO2 Enterprise Service Bus (ESB)**, is based on *Apache Synapse ESB* To provide a lightweight and highly configurable mediation platform, the WSO2 ESB allows administrators and developers to easily configure messages, connections, transformation, task scheduling, load balancing, and much more. Furthermore, it supports various integration patterns and allows for transport selection, rule-based mediation, and priority-based mediation. The WSO2 ESB is designed to transmit large datasets asynchronously and... *non-blocking*.
**WSO2 ESB 4.9** It offers several new features that support integration with Internet of Things projects, including:

- In addition to MQTT, they include HTTP, HTTPS, Java Message Service (JMS), Health Level 7 (HL7), Kafka, Apache CXF, and RabbitMQ protocols.
- The new WSO2 Enterprise Service Bus (ESB) store offers a wide variety of Connectors available for download. These connectors interact with a product's functionality and data, allowing your customers to interact with service APIs such as eBay, GitHub, Salesforce, and Twitter.

## **WSO2 Business Process Server 3.5**

**WSO2 Business Process Server** It provides an enterprise-level approach to managing business processes efficiently. Everything is powered by the engine. *BPEL Apache Orchestration Director Engine. He* It allows developers to easily implement business processes, as well as models that utilize the **Web Services Business Process Execution Language (WS-BPEL)**WSO2 BPS features a web-based graphical management console. This allows users to easily deploy, manage, and view processes and tasks.
With the version **3.5, WSO2 BPS** adds *motor Activiti BPM*, which supports BPMN 2.0, the specification recognized as one of the most *IoT-aware* for the modeling process. Thus, developers have the flexibility to use WS-BPEL or BPMN 2.0 to write their business processes, depending on their needs. In addition to Activiti, WSO2 BPS 3.5 enriches the BPMN 2.0 environment with:

- **A customizable web application for viewing and managing BPMN processes and tasks.**
- **Support for generating user task forms using BPMN.**
- **Functionality for publishing runtime statistics.**
- **Dashboard reports for BPMN and human tasks.**

## **WSO2 Data Services Server 3.5**

WSO2-*Data Services Server* allows database programmers to manage *web services* using company data.
Version 3.5 enables the use of RESTful APIs to query data from a variety of sources. In addition to relational databases, it allows previously inaccessible data sources to be exposed as APIs. This includes SQL (NoSQL) databases, file systems, content management systems, and others. Using the **OAuth 2.0** for authorization, the **WSO2 DSS 3.5** It adds the ability to access data from Google Sheets through an API. The open APIs, available through OData 4.0 and OAuth 2.0, work across the many platforms that organizations use.
