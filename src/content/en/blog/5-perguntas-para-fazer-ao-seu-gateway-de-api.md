## What questions should I ask my API gateway?

**1 – How can you help me delight my customers with rich and engaging digital experiences?** 

Assess how the provider can improve the interactivity and functionality of the applications, ensuring a fluid and enjoyable user experience.

**2 - How can you help me reduce my infrastructure costs?**

Investigate how the vendor's solution enables efficient resource management, whether through cloud, on-premise, or hybrid environments, with the aim of reducing operational costs.

**3 – How can you help me optimize my operations to deliver new applications faster?**

Discuss how the vendor can assist in implementing automation and continuous integration practices that accelerate the development and release cycle of new applications.

**4 – How can you help me increase the productivity of my organization and API developers?**

Explore how the supplier can simplify and automate processes so that developers can focus more on innovation and less on maintenance.

**5 - How can you help me make my applications more secure?**

See how the vendor integrates security practices and tools, such as advanced authentication and authorization, to protect applications against external threats and ensure compliance with **[security](/en/API-security%3A-check-out-the-top-10-security-flaws-in-OWASP./)** standards.

## **API Gateway:** **Security as a Priority
**

With companies increasingly relying on web applications to carry out their daily operations, **[security](/en/zero-trust-security-in-a-devsecops-strategy/)** has become an even more critical aspect in ensuring data integrity and confidentiality. In this context, the evaluation and selection of API gateways become fundamental, especially regarding the support they offer for advanced security protocols. Protocols such as OpenID Connect and mTLS (Mutual Transport Layer Security) are essential because they offer robust mechanisms for authentication and secure communication between services.

OpenID Connect, an identity-based authentication protocol, allows systems to verify a user's identity, while mTLS adds a layer of security by requiring both the client and server to authenticate each other before establishing a connection. These protocols are important because they help protect applications against a range of cyber threats, such as impersonation attacks and data interception.

In addition to supporting security protocols, it is vital that API gateways allow the implementation of advanced security and authentication policies. This includes the ability to configure granular access controls, monitor and log all access activities for auditing purposes, and ensure that all communications are encrypted.

Therefore, when choosing an API gateway, it is crucial to consider not only support for modern security protocols, but also the platform's flexibility to adapt and implement security policies that meet the organization's specific needs and current regulatory requirements. This approach not only strengthens the security of web applications, but also protects the company's reputation and the trust of its customers.
