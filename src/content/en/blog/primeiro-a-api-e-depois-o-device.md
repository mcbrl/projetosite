The development of applications has been so intensely shaped by mobile device trends in recent years that it has become common for many companies to focus primarily on tablets and smartphones, in what we have come to call "mobile first".

Although this is a sound approach for today, a certain lack of planning has led many developers to rethink their platforms at some point – because they haven't considered future possibilities for use, I'm referring to the near future.

The fact is, although the universe of mobile devices is growing in number and importance, PCs will still be around for quite some time, and as issues related to the development of IoT (Internet of Things) grow, more and more other devices will be connected, such as: cars, refrigerators, watches, glasses, glass screens, and so on. Designing strategies that disregard this fact risks having to redesign an entire architecture, because what was planned for a smartphone app may not necessarily meet the needs of some of these other devices. A similar situation is observed with companies that started by offering web services and later began offering mobile applications.

## API First

For this reason, the API First approach is gaining traction – it starts with developing an API that will support various possible platforms, and only then develops the user interfaces for those platforms. This approach allows for the standardization of functionalities across different platforms, including mobile devices: it becomes possible to find the same features in versions for iOS and Android from the earliest versions, for example.

This approach does not preclude the adoption of a "mobile-first" strategy; on the contrary, the careful design of an API will provide a solid foundation so that the mobile platform does not need to be rebuilt in the future if new platforms become necessary.

## Backend as a Service

The logic of defining a consistent API before starting interface development fits into a broader strategy known as Backend as a Service. The idea is to fully define the backend systems, encompassing cloud services such as storage, as well as support for push notifications, with the implementation of message queues, data sharing, and adjustments.

Defining APIs plays a fundamental role in the BaaS approach, serving as the focal point for future implementations. Careful API definition is crucial to project success, and the more complete the definition, including in terms of future expansion, the less need there will be to redesign the initial architecture.

## Developing the API culture

Understanding the importance of developing an API first and only then focusing on the interface can lead to the false impression that defining and implementing an API is a simple and easy task. In fact, it can be; but a lack of experience in the subject can lead many companies in completely wrong directions, due to a lack of knowledge of some of the best practices and the correct technologies for implementing each API as needed.

Seeking out experts in the field is always the best way to develop a culture within an organization, and leveraging knowledge in APIs is no different.

## Key Benefits of API First

API as an additional revenue source: Google makes the Google Maps APIs available so that Uber, 99 Taxi, or other companies can use this data to show passengers the location of their requested car, zoom in on the map, and even see the estimated time of arrival. ## Conclusion

An API-First strategy is a way for developers to connect their software and application to a device through an API call, without worrying too much about the device type.

One of the main reasons developers are choosing API-First is that building an app, starting with the mobile interface, takes time and resources, and then everything has to be redesigned for the new device. This means some processes need to be duplicated and then customized through various partners or people working on that solution. With API-First, you can build the objective of your solution without worrying about the front-end at that moment; the focus is on the solution, regardless of the operating system or device being connected. The main goal of this concept is to allow the API creation to happen with the specific solution it should serve in mind.

Developers strongly support the API-First approach because it eliminates redundant configurations and project rework. However, an API-First orientation is not for everyone. This type of orientation is data-centric and, if not managed correctly, can create security risks for the information being exposed.
